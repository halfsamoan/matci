# 개선 계획과 제품 방향

불만·미충족 요구·해결되지 않은 작업의 리뷰 기반 순위는 만들 근거가 부족하다(1개 긍정 발췌). 다음은 직접 사용자 요구와 기술 제약에 따른 우선순위다.

| 우선순위 | 문제 / 만들 동작 | 근거 | 크기/단계 |
|---|---|---|---|
| 1 | Linux 실제 RAM을 정확한 정의와 지표 종류로 보여주기 | 사용자 Ubuntu + L01/L02 | M / M1–M2 |
| 2 | 에이전트·터미널을 작업 중인 앱으로 보호, 무인 종료 금지 | S12 + Shell 관측 한계 L04/L05 | M / M1–M3 |
| 3 | 점유 추정과 전후 관측 변화를 구별 | S12 + L01 | S / M1–M3 |
| 4 | 쓰던 Archsport 노치 모션 유지, 동시에 켤 때 충돌 처리 | 사용자 명시 + A01 | M / M1–M2 |
| 5 | 정리 전에 대상과 이유를 검토하고 stale이면 거부 | L06 + 사용자 작업 보존 요구에 대한 설계 | M / M3 |

방향 후보: (A) 개발 작업을 방해하지 않는 Linux 메모리 도우미, (B) 숫자의 의미를 설명하는 GNOME 상태 노치, (C) 되돌릴 수 있는 파일 정리 도구. 현재 사용자는 Archsport와 코딩 도구를 함께 사용할 가능성이 높으므로 **A를 주 방향, B를 표면 UX, C는 후속**으로 선택한다. 사용자 리뷰로 검증된 시장 포지셔닝이라는 주장은 하지 않는다.
